# 功能探索

基于 2026-10-28 的当前源码，记录已接入的功能及后续可选能力。

## 优先级与范围

| 功能 | 当前状态 | 用户收益 |
| --- | --- | --- |
| 输出位置选择与同名处理 | 已实现 | 全局目录持久保存，同名自动编号 |
| 递归任务结果汇总与失败项重试 | 已汇总错误并保留失败任务；仅失败子目录重试待实现 | 明确知道哪些目录失败 |
| 保存与恢复整理方案 | 待实现 | 跨会话保留整理结果 |
| 真实导出进度与安全停止 | 已实现 | 实际处理数量反馈，停止时保留已有 PDF |
| 整理撤销/重做与跨页拆分 | 已实现 | 可撤销编辑，一张扫描图可对应左右两页 |

## 1. 输出位置选择与同名处理

主窗口新增全局输出目录，可选择、复制路径及恢复默认，重启后保留设置。目录通过 `--output-directory` 传入 Core；未设置时继续调用 Lua 的 `PathToSave`。

普通目录、压缩包及递归任务均使用该设置，文件名沿用来源名称。同名文件自动增加 `(1)`、`(2)` 等后缀，并发任务通过不覆盖目标的文件移动提交。

PDF 先写入目标目录中的唯一临时文件，成功关闭后才提交；失败或停止时临时文件移入回收站。默认路径、中文指定路径、同名保全及四进程并发编号已通过核心 CLI 定向检查；目录选择和设置持久化需要人工界面验收。

## 2. 递归任务结果汇总与失败项重试

`ExportController.cs` 检查所有子进程退出码并汇总错误。普通队列及递归父任务仅在全部成功后移除，停止或失败时保留当前任务。Core 的成功、失败及停止退出码分别为 0、1、2。

后续可以记录失败子目录列表，让下一次只启动失败部分。当前重启保留的递归父任务会重新处理其目录；成功文件通过同名自动编号保全。

仅失败项重试的验收应使用一个成功目录和一个失败目录，确认重试不重新生成成功目录。

## 3. 保存与恢复整理方案

现状依据：`ImgsToPDF.cs` 的 `organizedPages` 仅存在于内存，`DisplayPath` 会清空它。`GalleryForm` 已接受初始页面列表和 layout，可以复用恢复入口。`PageManifest` v1 是严格的七字段导出协议，未保存 `IsSelected`、layout 或来源目录；导出时也只写入已选页面。

最小会话数据包括版本、来源目录、全部页面的顺序与编辑、选中状态和 layout。沿用 `PageEdit`，使用独立会话文件，保留现有导出协议。缩略图、位图和预览缓存不写入方案。

恢复时校验来源与文件是否存在，列出缺失项；新增文件的追加规则与现有图库匹配行为保持一致。验收为整理后保存、重新打开并恢复，检查顺序、未勾选页、封面、裁剪和阅读方向。

## 4. 真实进度与安全停止

Core 在输入处理和 PDF 页面写入边界发出 `PROGRESS|processed|total|written`，提交成功后发出 `OUTPUT|path`。未开启 `--progress` 时保持标准输出安静。

主窗口显示当前来源的已处理图片数、总输入数及已生成 PDF 页数；双页模式分别统计输入和输出。递归任务仍限制最多四个核心进程，进度文案注明当前来源。后台参数使用启动时快照，控件通过 UI 上下文更新。

导出时开始按钮切换为停止，通过命名事件通知活跃核心进程；统一宽度预扫描、页面边界和解压条目边界检查停止。关闭窗口时先等待合作停止及资源释放。核心停止、既有 PDF 保全和临时文件回收已通过 CLI 定向检查；界面停止与关闭交互需要人工验收。

## 5. 编辑撤销与扫描拆分

图库提供撤销/重做按钮，以及 `Ctrl+Z`、`Ctrl+Y`、`Ctrl+Shift+Z`。最多保存 50 步元数据历史，覆盖顺序、勾选、旋转、裁剪、封面、布局和拆分；历史不持有图片位图。

右键“拆分左右页”将当前旋转后的裁剪区域等分为两个独立逻辑页；右至左布局中右半在前，其余布局左半在前，封面只保留在第一逻辑页。图库恢复和主窗口导出保留重复源路径。全局重置合并回一张源图一页，该操作可撤销。同源两个裁剪页的核心导出已通过检查；完整编辑与历史交互需要人工验收。

## 建议实施顺序

后续候选为整理方案持久化及仅失败子目录重试。大量人工整理的使用场景优先接入会话保存；递归批量转换的使用场景优先接入失败项重试。
